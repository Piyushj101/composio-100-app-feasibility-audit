The agent — three passes, not one

Real HTTP fetches against the docs URLs from the assignment sheet, run in this pipeline.
01 · fetch_agent.py

Automated scrape

Hits the real hint URL for all 100 apps, records status/redirects, and keyword-matches the HTML for auth, API-shape, and self-serve vs. gated signals. Zero human input.

94/100 URLs fetched
02 · knowledge_base.py

Reviewer merge

A knowledgeable reviewer reads the agent's raw signal + fetched pages and writes a judgment per app, tagging every row high / medium / low confidence before checking anything externally.

Agent-alone agreement: 18.1%
03 · verification_log.py

Live-search verification

Real web searches against a sample, weighted toward the lowest-confidence rows, cross-checking claims against current docs and pricing pages before anything gets published.

Where a human was needed, concretely: deciding what "self-serve" means per product (a free dev sandbox vs. a real production key are different claims); reading pricing pages to find plan-gates the scraper can't parse; resolving name collisions (e.g. two unrelated products both called "Otter"); and — critically — running the search-verification loop below, which a keyword scraper cannot do on its own.

What the agent got wrong, said plainly

Corrected after verification (4)

  • Pylon — assumed a paid-plan API gate that doesn't exist; any Admin can self-serve a token.
  • Waterfall.io — couldn't identify the product from the hint alone; it's a real, self-serve B2B enrichment API.
  • fanbasis — assumed no public API existed; it has one, but the docs portal itself needs a login (a different blocker than we guessed).
  • Otter.ai — training-era knowledge said "no API"; it shipped one in 2025. A knowledge cutoff, not a scraping failure.

Refined, not wrong (1)

  • Ahrefs — the "paid-plan gate" direction was right, but the specific claim ("Enterprise-only") was stale; 2026 sources show it widened to the Lite tier.

Still low-confidence, unverified (11 of 100)

    Not really API products at all (2)

    • Sherlock and Mermaid CLI are open-source local tools with no hosted service or auth — a toolkit would shell out to them, not call an API. Included as-is because the brief asked for a verdict on all 100, not just the API-shaped ones.
